# 已知限制与验证边界

本样例使用通用制造业合成数据，不承诺生产质量、容量或 SLO。离线测试和 CDK synth
不能替代目标账号的身份、网络、权限与负载验证。

## 名词解释

| 名词 | 含义、发生时机与优化边界 |
| --- | --- |
| 冷启动 / 热请求 | 冷启动发生在 Lambda 为请求新建执行环境时，首次请求要等待环境和应用准备；热请求复用已准备的环境。耗时和优化选项见后文，不设固定单次耗时。是否为冷启动须检查平台 `Init Duration`，不能仅凭“第一个请求”或等待时长判断。 |
| 平台初始化（Init Duration） | Lambda 准备运行环境、加载已发布代码和依赖、执行初始化代码的时间。应用不能直接控制平台准备，但依赖大小和初始化代码会影响其中部分工作；应在目标环境分别测量。 |
| 首次初始化（handler factory） | 创建配置、SDK 客户端和服务对象的工作。按需模式在首次调用中执行；REQUEST PC 模式在 Init 预建。两种模式须分开计时，不能把调用内 factory 近零解释为初始化没有成本。 |
| 预置并发 | 提前准备指定数量的 Lambda 执行环境。REQUEST 示例默认 0；容量外仍可按需冷启动，且不能代替整个 Search 链路的初始化。 |
| p50 / p95 | 把样本耗时从小到大排序后的分位数。p50 描述中间水平；p95 描述接近最慢一端的水平。通常可读作“每百次约有九十五次不超过该值”，但小样本不能直接代表长期分布。 |
| embedding（向量表示） | 模型把查询或工具描述转换成数字数组，搜索用这些数字比较语义相近程度。在线查询和后台工具索引会调用模型；失败路径预算见后文。缓存、模型和网络选择可影响耗时，健康模型的固定耗时未核实。 |
| 降级（BM25） | 向量不可用时，改用 BM25 词法评分：按查询词与工具文本的匹配程度排序。权限检查仍执行，语义召回能力可能下降；BM25 本身不调用 embedding 模型。纯词法阶段耗时须单独测量，本文不提供未经核实的数值。 |
| 拦截器 | Gateway 在调用目标工具前执行的 REQUEST 函数。它校验身份、检查权限和限流，并为 Search 添加可信签名上下文。冷执行耗时须单独测量，可优化初始化和依赖访问，不能省略权限检查。 |
| MCP target | Gateway 后面实际提供工具的目标服务。本项目的 Search target 是一个 Lambda 目标，通过 MCP 工具调用协议返回可用工具。分派发生在拦截器之后；其独立网络耗时未核实，应用优化范围见后文。 |
| OIDC / JWKS | OIDC 是身份认证协议；JWKS 是身份提供方公开的签名验证密钥集合。预置并发 Init 预取、首次认证、缓存过期或遇到新密钥时可能访问这些端点；缓存和有界重试可减少部分失败，但不能取消签名校验；读取耗时受身份服务和网络影响，固定耗时未核实。 |

## 冷启动与容量

平台初始化、首次应用初始化、身份元数据读取和快照加载都会影响首请求。
分别测量闲置首批、并发突发、热请求和后台刷新，不用单次热请求代表用户体验。
函数默认尺寸与快照准入规则见[容量说明](capacity.md)。

## 依赖 REQUEST 预热或启用 PC 前的条件

当前 [Init 预取](../src/semantic_service/_request_prefetch.py)只要发现 JWKS 中有一个被拒的 key，
就把整次预取记为失败并恢复旧缓存；[请求认证](../src/semantic_service/auth.py)则保留通过校验的签名公钥。
因此混合签名/加密密钥或多算法集合可能使请求验证成功而预取失败。
依赖预热前，应验证目标 IdP 的完整密钥集合及轮换过程，并解决两条路径的策略差异；
预取失败告警不能直接等同于请求认证不可用。样例默认预置并发为 0。

预取缓存的 300 秒 TTL 从 Init 中成功刷新时开始。若首请求在 Init 后超过 300 秒才到，
仍要同步读取 discovery/JWKS，预取对该次认证的缓存收益为零。
预取在父进程内使用独立 HTTP 客户端及 verifier，结束时关闭，不预热请求客户端的 HTTP 连接池。
请求客户端的连接池默认空闲保留时间为 5 秒；冻结后上游是否仍保留连接须在目标环境验证。

预取的 3.0 秒是单调时钟软截止；默认 2.75 秒用于工作，最多 0.25 秒用于清理。
父进程只在主线程可独占 POSIX `SIGALRM` 定时器时执行预取；非主线程、信号已屏蔽、
已有 pending 信号、现有定时器或自定义 handler 均跳过预取并记录 `structural`。
原生 DNS `getaddrinfo`、不可中断的清理与调度可能延迟信号处理，因此不是硬实时保证。
此前 factory、模块导入和平台准备，以及随后 Init 摘要输出均不含在这项预算内。
完整契约见[服务配置](service.md#冷启动分段计时)。

## ECS 后端的已知问题

ECS 默认关闭。下面保留源码相关问题及验证要求；公开整理没有修复这些行为。
启用前需解决适用问题，验证故障回退、密钥轮换、长期闲置、自动伸缩和通知送达。

| 发现 | 缺陷与影响 | 再次启用前的关闭条件 |
| --- | --- | --- |
| ECS 故障未进入回退 | [facade](../src/semantic_service/facade.py)把部分 HTTP 408/431/500/404/413 响应及部分不可重试的内部故障 503 判为终局错误；即使路由预算仍充足，也不会启动 Lambda 回退。已测的 `capacity` 回退不能覆盖这些服务故障。 | 修正传输故障、内部故障与业务拒绝的分类，让需要回退的故障进入 Lambda，同时保持认证、授权和输入拒绝的安全边界；对故障分类逐项验证实际路由、剩余预算及终局响应。仅扩充 HTTP 状态允许清单不足以关闭此项。 |
| 共享资产守卫只比较路径 | [资产选择](../infra/assets.py)及[synth 入口](../scripts/synth.py)接受不同路径下内容相同的共享 ZIP 和 ECS ZIP。一次 ECS 启用可能同时更新既有 Search、Indexer、Enhancer 的代码和 alias，破坏保留既有部署共享资产的范围约束。 | 将共享资产与批准的既有部署内容摘要绑定，并核对候选模板内既有函数的 Code、Version 和 alias；验证改名或复制同一 ZIP 不能绕过守卫。不能以路径不同代替内容一致性证据。 |
| ECS 开关扩大既有告警通知范围 | [配置校验](../infra/config.py)强制 ECS 配置提供 SNS topic，[通用监控](../infra/monitoring.py)再把动作加到全部既有告警。计划任务默认关闭时，缺少 poll 指标的告警会持续告警；有意的输入或认证拒绝也可能触发 Lambda 错误通知。 | 分离 ECS 告警与既有 Lambda 告警的通知配置，按计划任务是否启用处理 poll 告警，并确认有意拒绝的通知策略；验证启用 ECS 不会未经选择改变既有通知动作及其告警语义。 |
| HTTP 头部预算小于可接受 token | [ECS HTTP 服务端](../src/semantic_service/ecs_server.py)的 16384 字节预算覆盖请求行和全部头部，小于[后端认证](../src/semantic_service/ecs_backend.py)宣称接受的 token 及 Authorization 长度。接近上限的合法 token 在到达认证前即收到 431，并受回退分类问题 的终局错误影响。 | 统一 token、Authorization、请求行和其他头部的长度契约；用接近上限的合法 token 和超限请求验证服务端、后端及 facade 行为，同时保留明确的总头部上限。 |
| 空闲连接被头部定时器提前关闭 | [ECS HTTP 服务端](../src/semantic_service/ecs_server.py)等待下一请求行之前就启动默认 1 秒的头部定时器，空闲 keep-alive 连接因此早于 60 秒连接期限被关闭。facade 常需重新握手，关闭与写入交错时还可能触发一次协议错误回退。 | 区分空闲连接期限与新请求头部读取期限，保持慢速请求防护；验证超过 1 秒间隔的连接复用、预期关闭行为，以及关闭与下一次写入竞争时的处理。 |
| 业务拒绝清空回退连接池 | [Invoke 所有权管理](../src/semantic_service/invoke_ownership.py)在任何异常离开调用区间时关闭专用 Lambda 客户端，而[回退响应分类](../src/semantic_service/facade.py)也在该区间内抛出业务或容量异常。正常返回的非 OK 响应因此清空 HTTP 连接池，使下一次回退多一次握手。 | 只对真正被中断或不再安全的 Invoke 连接执行必要清理；验证业务拒绝、容量响应和成功响应后的客户端复用，并保留截止时间中断后的连接隔离与资源释放。 |
| 部署和回滚准备期的告警 | [ECS 监控](../infra/ecs_search.py)将任务数和健康 target 数的缺失数据连续两分钟视为故障，但启动宽限为 210 秒，部署或回滚的准备窗口足以触发 SNS。单次 TLS 协商错误也会越过零阈值。 | 使告警评估覆盖启动、滚动部署和回滚的实际生命周期，明确 TLS 瞬时失败的通知策略；验证正常部署和回滚不产生预期内噪声，同时真实任务丢失、target 不健康和持续 TLS 故障仍能被及时发现并送达。 |

## embedding 超时与词法降级

[Search 服务](../src/semantic_service/search.py)默认给搜索处理设置 3.0 秒预算，
授权和快照加载会消耗其中一部分。provider 截止时间取配置期限与 Lambda 剩余期限的
较早者，仅在 Lambda 分支扣除 300 ms 收尾余量；缺少或无法解析 Lambda 剩余时间时
沿用配置期限。Lambda 余量充足时，不会从默认 3.0 秒配置预算中再扣 300 ms。
[检索核心](../src/semantic_core/search.py)把 embedding 子预算限制为剩余 provider
预算与配置值（默认 1000 ms）的较小值。首次模型凭证获取和响应处理也会占用子预算。
模型子预算允许 `(0, 6]` 秒，Search 总预算允许 `(0.3, 6]` 秒，均须为有限数值；
具体公式与异常诊断见[embedding 诊断](embedding-diagnostics.md#可配置预算与授权收尾)。
这些是协作期限，阻塞操作仍可能超期，不能承诺硬性按时返回。
降级能保持已授权范围内的词法发现，但对同义改写、中英文表达差异的处理可能弱于向量搜索。
调用成功、命中预期工具和模型调用成功是不同结果。
运维应同时查看 `degraded`、`vector_availability` 和 `embedding_error`；
分类说明与排查步骤见[错误诊断](embedding-diagnostics.md)和[运维手册](operations-runbook.md)。
权限或索引完整性无法验证时仍拒绝请求，不采用 BM25 绕过检查。

## 客户端看到的工具约束

示例 Search metadata 只声明对象类型、`query` 与 `_auth_context` 字符串及必填 `query`，
见[合成 schema](../tests/fixtures/service/search-schema.synthetic.json)。这是支持的 metadata 子集，
不是某个部署的服务捕获。运行时仍检查查询非空、最长 2048 个字符、未知参数、
签名封套长度及绑定关系。客户端须省略 `_auth_context`，交给拦截器填入。
描述符摘要参与授权，变更必须走[部署校验](deploy.md)。

## 质量和容量报告不能替代验收

真实模型参考仍使用合成查询，采用历史排序配置，部分调用顺序固定。
先搜索减少模型输入，也可能漏掉正确工具，详见[实验摘要](../reports/real/knee-comparison.md)。
原始运行数据不随样例发布，摘要不作为当前默认的质量验证。
用人工标注查询、权限负例及你的真实工具描述，分别验收召回、选择和业务执行。
动态工具列表不进入共享索引；业务资源权限仍由业务工具负责。
